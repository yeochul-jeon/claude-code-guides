### 하네스 엔지니어링 방법론 (438줄)

핵심 주장: `Agent ≠ Model`, `Agent = Model + Harness`

9개 섹션 구성:
1. 하네스 엔지니어링이란? — 벤치마크 근거 (49.5 → 79.3, 60% 향상)
2. 소프트웨어 추상화의 역사 — Compiler → Framework → AI Harness 계보
3. **4기둥 프레임워크** — Runtime Constraints / System Enforcement / Auto-Correction / Evolutionary Cleaning
4. **결정론적 vs 확률적 통제** — Hooks(100%)와 CLAUDE.md(~80%)의 근본적 차이
5. **에스컬레이션 패턴** — 1회 반복→대화 / 2회→CLAUDE.md / 3회→Hook 강제차단
6. 3 성능 축 — Accuracy / Safety / Efficiency 삼각형
7. **If-Then 규칙 엔진 패턴** — 모호한 가이드라인 대신 조건-행동 테이블

9. 개발자 역할의 변화 — Author → Curator

## 대화 중 주요 논의

### MCP 컨텍스트 비용 수치

"MCP 서버 5개를 활성화하면 대화 시작 전에 컨텍스트의 41%가 소진된다"는 수치를 개인설정 가이드에 추가. 이 수치는 도구 스키마 기반 추정치로, 실측값과 편차 있을 수 있음 — 표에는 `~` 기호로 근사값임을 명시.

### 하이브리드 워크플로우 사이클

Hooks 섹션에 단순 "결정론적 실행"이라는 설명 외에, **워크플로우 전체 흐름에서 어떤 위치**를 차지하는지 명시하는 것이 이해에 유리하다고 판단:
- `AI 생성(확률적) → PostToolUse Hook(결정론적) → 독립 리뷰(확률적) → CI(결정론적)`
- "확률적"과 "결정론적"이 교차하는 구조가 하네스의 핵심이라는 점을 시각화

### 번호 체계 소수점 방식

기존 가이드 목차 번호(1~5)를 재정렬하면 모든 내부 링크/북마크가 깨질 위험이 있어, 소수점 번호(2.5, 2.7, 3.5)로 삽입하기로 결정. 추후 문서 수가 더 늘어나면 정수 번호로 재정렬 고려.
