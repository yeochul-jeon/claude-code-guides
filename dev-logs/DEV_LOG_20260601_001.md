## 대화 중 주요 논의

### 1. Karpathy 4원칙의 기존 커버리지 격차 분석

Explore 에이전트 탐색 결과, 4원칙이 기존 문서에 어떻게 매핑되는지 확인했다:
- Think Before Coding → 예시 블록 안에 격언으로만 산재 (체계적 섹션 없음)
- Simplicity First → **전무** (Over-Engineering이 실패 패턴으로 명명조차 안 됨)
- Surgical Changes → Shadow Agent 패턴으로 충실히 커버
- Goal-Driven Execution → **가장 약함** (success criteria 명시적 섹션 부재)

이 격차 분석이 Broader 범위 결정의 근거가 됐다.

### 2. advisor 권고 반영 사항

- 범위 결정을 AskUserQuestion으로 사용자에게 위임 → Broader 선택
- upstream 저장소 확인 (multica-ai가 forrestchang의 미러임을 확인)
- 검증 불가 데이터(X 트윗 날짜·스타 수치) 제외 → 실제로 가이드에 넣지 않음
- "4가지 실패 패턴" 헤딩 유지로 앵커 안정성 확보

### 3. Goal-Driven vs Eval Coverage 개념 구분

방법론 §6에 Goal-Driven을 넣을 때, 기존 "축3 Eval Coverage"와 혼동될 수 있어
두 개념의 레이어 차이를 명시했다:
- Eval Coverage = 하네스 전체의 검증 체계 (macro)
- Goal-Driven = 개별 작업 시작 전 성공 기준 정의 (micro)
