### 2. YouTube 자막 추출 — yt-dlp 채택

- curl 직접 호출: PoToken 제한으로 빈 응답 (프로브로 확인됨)
- pip/pip3: PEP 668 브레이킹 패키지 설치 거부
- `brew install yt-dlp` 성공 → `--sub-langs ko --sub-format json3` 추출 (248KB, 832초 영상)
- ASR 자막이라 구두점·영어 용어 왜곡 존재 → 항목 요지 파악 목표로만 사용, 축자 인용 금지

### 3. 항목 수 불일치 처리

영상 제목 "20가지" ↔ 오프닝/마무리 "23가지" ↔ ASR 식별 16개.
추측으로 나머지 7개를 채우지 않고 식별된 16개만 분류 후 메모로 명시 — 정직성 원칙 준수.

## 대화 중 주요 논의

### 1. yt-dlp vs 다른 접근법 선택

plan 단계에서 curl 직접 접근이 PoToken으로 막힘을 확인 → brew install yt-dlp가 가장 경량하고 안정적인 경로.
PEP 668 제한(Homebrew Python의 외부 패키지 설치 보호)은 pip이 아닌 brew 패키지 경로로 우회.

### 2. 단순 요약 vs 갭 체크

advisor: "입문 영상이라 20개 항목 대부분이 기존 가이드와 중복될 가능성이 높다. 재서술하면 문서 가치가 없어진다." → 갭 체크 구조(분류+매핑)가 핵심. 실제로 ✅ 커버는 1건뿐, 🆕 신규가 8건으로 예상보다 새 항목이 많았음.

### 3. B4 공식 문서의 높은 밀도

code.claude.com/docs/ko/best-practices는 WebFetch로 전체 내용 확보. 공식 1차 출처로 확정 가능한 항목(Stop hook 8번 수치, --allowedTools 구문 등)이 다수 포함되어 보조 자료 중 가장 가치 있는 자료였음.
